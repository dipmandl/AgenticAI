# Requirements Analysis Skill

## Purpose
Interpret requirements and acceptance criteria in a traceable, reviewable way.

## Use when
- The project receives a story or requirement.
- The system needs a structured requirement analysis artifact.

## Key outputs
- Requirement IDs
- Business expectations
- Acceptance criteria
- Missing information or ambiguities
- Out-of-scope items

## Rules
- Do not invent missing business requirements.
- Ask for clarification when critical information is missing.
- Keep requirement facts separate from assumptions.
