# Test Review Skill

## Purpose
Guide independent review of generated test cases for coverage, Gherkin validity, and traceability.

## Review process

### Step 1: Coverage check
For each acceptance criterion in `requirement-analysis.md`:
- Find at least one TC that covers it (positive scenario).
- Verify a negative scenario exists if the AC implies error behavior.
- Verify a boundary scenario exists if the AC mentions limits.

### Step 2: Gherkin validity
Each scenario must:
- Have exactly one `Feature` block per file.
- Have at least one `Scenario` (or `Scenario Outline`).
- Each scenario must have: `Given` (or `Given` implied), `When`, `Then`.
- `And` / `But` are valid only after `Given`, `When`, or `Then`.
- No `Given` after `When`. No `When` after `Then`.

### Step 3: Tag consistency
Each scenario must have:
- `@TC-NNN` — matches a TC-ID in the test plan
- `@REQ-NNN` — matches a REQ-ID from requirement analysis
- At least one category tag (`@ui`, `@api`, `@e2e`, `@functional`, etc.)
- At least one priority tag (`@smoke`, `@regression`, `@critical`, `@medium`, `@low`)

### Step 4: Duplicate detection
Two scenarios are duplicates if they share:
- The same `TC-ID` tag, OR
- Identical `Given/When/Then` steps with the same data values

### Step 5: Scope check
No scenario should test behavior explicitly listed as out-of-scope in the test plan.

## Finding severity
| Severity | Examples |
|----------|---------|
| FAIL | Missing acceptance criterion coverage, invalid Gherkin syntax, duplicate TC-ID |
| WARN | Missing boundary scenario, inconsistent tag, step wording ambiguous |
| INFO | Minor wording suggestion, cosmetic |

## Auto-correction rules (when configured)
The review agent may auto-correct:
- Gherkin keyword capitalization errors
- Missing TC/REQ tags (add based on test plan mapping)

The review agent must NOT auto-correct:
- Scenario step content
- Acceptance criteria
- Scope of existing scenarios
- Pre-existing test files not generated by the current pipeline run
