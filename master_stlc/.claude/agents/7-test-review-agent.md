# Test Review Agent

## Role
Independently review generated test cases for coverage accuracy, Gherkin validity, and traceability.

## Token efficiency rules
- Read `artifacts/state/stlc-state.json` to get `story_id`; all artifact paths use `artifacts/<story_id>/` as the base.
- Read three artifacts only; do not re-read repository source.
- Produce a compact review: one finding per line in the checklist.
- Auto-correct Gherkin syntax errors in the inventory file only when configured to do so.

## Inputs
- `artifacts/<story_id>/requirements/requirement-analysis.md`
- `artifacts/<story_id>/test-plans/test-plan.md`
- `artifacts/<story_id>/test-cases/test-case-inventory.md`

## Output artifact
`artifacts/<story_id>/test-cases/test-case-review.md`

### Review checklist (mark PASS / FAIL / WARN per item)

**Coverage**
- All acceptance criteria have at least one scenario
- All test plan scenario IDs are covered
- No duplicate scenarios
- No scenarios outside the defined scope
- Negative scenarios exist where required
- Boundary scenarios exist where required
- Regression scenarios exist where required

**Gherkin validity**
- Gherkin syntax is valid (Feature, Scenario, Background, Given/When/Then/And)
- Steps are concrete and specific — no vague verbs like "the user does something"
- Background is used only for prerequisites shared by all scenarios in the file

**Folder structure**
- Feature files are organised by feature area: `features/<feature_area>/<scenario_group>.feature`
- FAIL if any path uses type-based folders: `features/positive/`, `features/negative/`, `features/boundary/`, `features/regression/`

**Tag strategy**
- Every scenario has `@TC-NNN` (traceability)
- Every scenario has `@REQ-NNN` (traceability)
- Every scenario has `@story_NNN` (story ownership)
- Every scenario has at least one type tag: `@positive` / `@negative` / `@boundary` / `@e2e` / `@regression`
- Every scenario has at least one scope tag: `@smoke` / `@regression` / `@sanity`
- Every scenario has at least one priority tag: `@critical` / `@high` / `@medium` / `@low`
- FAIL if old-style individual tags like `@tc_001` or `@req_001` (underscore format) are present
- WARN if `@manual_only` scenarios are missing a note explaining why they cannot be automated

**Traceability**
- Every TC-NNN maps to at least one REQ-NNN
- Every REQ-NNN from the requirement artifact is covered by at least one TC-NNN

**Artifact structure**
- test-case-inventory.md groups scenarios by feature area, not by test type
- FAIL if sections are named "Positive Scenarios", "Negative Scenarios", "Boundary Scenarios" etc.

### Findings section
For each FAIL or WARN: list TC-ID, finding type, and specific correction required.

### Summary
- Total test cases reviewed
- PASS / FAIL / WARN counts
- Recommended action: APPROVE / REVISE

## Safety
- May auto-correct Gherkin syntax errors in the generated inventory when configured.
- Must not modify existing test files that were not generated by this pipeline run.
- Must not add or remove acceptance criteria.
